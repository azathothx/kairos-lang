  - **問い**＝結合子で覆域つきの表と結合した列の後段の `at` が註釈区間の点を落とす（素の列は点保持＋註釈）規約差を統一するか。
  - **事実**＝現状は ADR-37 判断 4 の輸送表の帰結そのもの——結合子行（両辺の註釈の和・値は切らない＝判断 1）と filter 行（述語が
    範囲外参照を要求した点は落として註釈＝判断 6）。`at` の展開は tick＋`coincides`（述語・ADR-51）で、ADR-51 追記 2（2026-09-03）が
    「at の内部 filter を規約の外に置く特別扱いはしない（糖衣は展開先の意味を継承する）」と既に位置づけている。原理＝結合子は
    **存在が判っている点**に完全性の註釈を添えるが、述語は**真偽が未知**の点を主張できない（∃ は単調＝証人規則・ADR-38 判断 4）。
    規約差は段の都合ではなく「点の存在が既知か／述語の真偽が未知か」の差。
  - **案 ①**（証人規則の緩和＝at 段も点保持）＝「存在するか判らない点に時刻を貼って出す」ことになり、述語の規約（ADR-37 判断 6）と
    証人規則（ADR-38 判断 4）の両方に例外を作る。壁時計を保つ点変換は core に無く（経過算術形は DST でずれる＝ADR-51 の出発点）、
    述語を経ない展開に書き換える道もない。不採を推奨。
  - **案 ②**（素の列も落とす）＝値を切る刃は言語に無い（ADR-37 判断 1）に反する。不採（既裁定）。
  - **案 ③（推奨）**＝現状維持。規約差を上の原理（存在既知／真偽未知）として明文し、説明責任を文書で果たす。処置＝文書のみ
    （at.md・combinators.md は明文済み。spec §4.8 糖衣か §4.9 coincides に「糖衣は展開先の輸送行を継承する」の 1 文があるか確認し、
    無ければ追記）。分類＝［明文化］（意味論不変）。再開条件＝実害（運用者が点の脱落で発報を落とした実例。第 15・20 便は観測のみ・
    運用の防御は覆域の更新＝ADR-37 判断 8）。
  - **推奨＝③**。
- **裁定（2026-10-01・設計者）＝案 ③（現状維持＋明文）**。spec §4.8 に「糖衣は展開先の意味（註釈の輸送行・DST 規約）を継承する——
  段ごとの規約差は『点の存在が既知か／述語の真偽が未知か』の差」を明文（日英・1.0 追補 23 に同乗）。**設計者の回顧**: 「そもそもこれも
  グレゴリオ暦由来だと思う。もとより糖衣なのだから、求める時点が属する区分を含む premise においてその区分のひとつ上位の区分のある
  時点を A としたとき [A, A+1) の間のどこかを指すもの、としておけばよかったのかもしれない。そうすればそれはその premise の責務と
  できた」——当方の読み: 問題（註釈区間の点が述語で落ちる）は暦法に依らないが、`at` が述語になった**理由**（市民日グリッドの tick に
  `coincides` を重ねる展開）はグレゴリオの機構に依っている。回顧の定義なら `at` は窓内位置の射影＝点変換で、1-4・窓付き入力の禁止・
  endless の素通しが同時に消える。要るのは premise が提供する「上位区分の窓内の位置」の射影語 1 本と ADR-51 の改訂＝90 の 3-16 に
  追加拡張として採録（記録のみ・需要が立ったら）。

### 1-2 表示形の一意性（秒未満・DST の重複）

- **表示形の一意性（秒未満・DST の重複）［裁定待ち・表面の契約］**: 同上の採録。表示形 `YYYY-MM-DD[Thh:mm[:ss]]` は
  ms もオフセットも印字しない——秒未満の点（`strideBy(0.5s)`・秒未満を持つ供給の instants）は同じ表示形が続き、DST の
  重複時は同じ壁時計が 2 回出て逆行する（NY 2026-11-01 の 01:30 → 01:00）。`--json` の `points` は一意で昇順。
  候補＝ms が 0 でないとき `.SSS` を添える／重複の 2 回目にオフセットを添える／現状維持で「判定は points」を明文。
- **仕分け（2026-10-01）＝参照実装の表示の規約→87 §6 の 9 へ合流**。表示形は spec が規定しない
  射影（ADR-11・7 節）で、出所は `rt.fmt` の 1 箇所。六十干支のラベルなら「同じ日の点は同じラベル」が自明で、表示を点の同一性と
  読む者はいない——グレゴリオの秒付き表示が「ほぼ一意」に見えるために問題に見える形。`--json` の `dates` は `fmt` の出力なので、
  人間表示の規約と Schema の `dates` の説明は同時に決める。言語側＝明文化候補 (a)「点の表示は射影・同一性は点が担う」のみ。
- **裁定（2026-10-05〜06・設計者）**: 言語の裁定ではない（ms の粒度の是非は言語で判断しない＝premise・実装の領分）。参照実装の表示規約＝
  秒と同じ適応表示で ms が 0 でないときだけ `.SSS`・DST の重複（同じ壁時計が二度ある瞬間）は 1 回目・2 回目ともオフセット `±HH:MM` を
  添える（案 B）→ **`dates` は `points` と一対一**（設計者の理解「結果の時間ストリームは日時文字列の羅列ではなく DateTimeOffset のような
  オブジェクトの列」＝点〈同一性〉と射影〈ラベル〉の対＝JSON の points／dates）。導出規約（最初の出現＝ADR-31 改訂 2）と点の非併合は
  不変。処置＝impl/src/tz.ts `format`・doctest 2 本の期待出力（everyInstant の 1 sol・09-dst の秋戻し）・witness 4 本・Schema の `dates` の説明。

### 1-3 供給の `asof` の形式

- **供給の `asof` の形式［裁定待ち・契約］**: 境界チェックリスト一巡目の軽微 17。`"yesterday"` も通る。日付
  （`YYYY-MM-DD`）に限ると、版名や日時を asof に入れている供給側が割れる——実装系の実態を聞いてから。
- **仕分け（2026-10-01）＝供給契約（wire）の規約→87 §6 に 10 として新設**。言語側の asof は
  「版」（spec §3.8「版は `asof:` が担う」・ADR-46＝解決値が必ず運ぶ・宣言 asof と不一致なら被覆サマリに常時表示）であり、参照実装も
  文字列の同一性比較と表示・メモ化鍵にしか使わない（日付として読まない）。六十干支でも供給には版が要るが、版が日付である必要は
  ない。言語側＝明文化候補 (b)「asof は版の識別子＝同一性比較のみ・順序を読まない」を spec §3.8 に 1 行（Schema と同じ公開）。
  供給 JSON の `asof` に `YYYY-MM-DD` の pattern を掛けるかは供給側の実態（寒露便で照会）を聞いてから 87 で決める。
- **裁定（2026-10-06・設計者）＝推奨案＝任意の非空文字列（同一性比較のみ・順序を読まない）**。理由（設計者）「premise 内の asof がその
  premise の語彙に縛られるのは許容するが、言語全体の現在地の指定機構が一 premise に過ぎないグレゴリオ暦に縛られるのは望ましくない」。
  処置＝spec §3.8 に 1 行（日英）・供給 Schema の `asof` は minLength 1＋説明（版を切る識別子が無ければ観測日 YYYY-MM-DD を推奨）。
  供給側の実態（寒露便 10/8）は参考として確認（Schema を変える見込みは低い）。

### 1-5 CLI の JSON 出力（CliReport）の形

- **`results[].source` の意味とエラー時の形［裁定待ち・表面の契約］**: 2026-09-30 境界チェックリスト三巡目（`--json` の不変条件
  30 本）で採録。(1) `results[].source` は必須の文字列だが、参照実装は**常に空文字列**を出している——式の字面を入れる

  stdout が空・stderr に文言・終了コード 1 で、JSON の形ではエラーを返さない——機械の消費側に `{error: …}` の形が要るか。

- **仕分け（2026-10-01）＝wire の規約→87 §6 の 8・9（転記済み）で裁定**。言語には無関係（CLI は参照実装）。
  本項は 87 の裁定が済んだら閉じる。
- **裁定（2026-10-06・設計者）**: `results[].source`＝式の字面に加えて **`line`**（1 起点の行番号。「同じ source なのに直前 premise の違いに

  4＋7（設計者「無理ない程度で」「入れるなら explain と同時」→一本化）。
