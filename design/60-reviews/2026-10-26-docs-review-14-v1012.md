### HIGH

#### ①-H1 日本語 README の最初のコード例が、CLI・MCP・Playground のどれでも実行できない

- **何が**: README.ja.md:11-16 の冒頭の例
  ```text
  premise JP { calendar-system: Gregorian; calendar: TSE; tz: "Asia/Tokyo"; wkst: Mon }

  @JP
  monthEnd |> roll(Preceding, on: bizDay) |> shift(-3, unit: bizDay)   # 毎月末の 3 営業日前
  ```
  は `calendar: TSE` を参照するが、`TSE` というカレンダー実体は npm パッケージの stdlib（gregorian／fiscal／isoweek の 3 本）にも Playground（`playground/core.js`・`app.js` に `calendar: TSE` は 0 件）にも存在しない。英語 README（README.md:18-26）と llms.txt:60-68 の同じ趣旨の例は祝日表と `bizDay` 導出を書いた自己完結形で、こちらは実行できる。
- **どこで**: README.ja.md:12（`calendar: TSE`）。日本語を正とする言語の、日本語 README の最初の例。
- **再現**:
  ```
  $ node impl/dist/cli.js list readme-ja.kairos --from 2026-01-01 --to 2026-07-01
  calendar: が指す premise が未定義: TSE
  EXIT=1
  ```
  MCP `kairos_validate`（npx -y kairos-lang-mcp@1.0.12・同じ source）→ `{"ok":false,"version":"1.0.12","diagnostics":[{"kind":"static","message":"calendar: が指す premise が未定義: TSE"}]}`。
  比較: README.md:19-25 を同じ条件で → `2026-01-27T14:00 … 2026-06-25T13:00`（6 点・終了 0。時刻付きで出る件は M2）。
- **影響**: 新規読者が README.ja.md の例を Playground に貼ると最初の一歩で静的エラーに当たる。README.ja.md:60「まずブラウザで試す」の直後に起きる。`TSE` が spec の説明用の名前（spec/20-premise-layer.md:43・spec/90-examples.md:61・reference/README.md:76 の doctest 標準前提）であることは、README だけを読む人には分からない。
- **直し方の案**: README.ja.md の例を README.md と同じ自己完結形（表 `covering: 2026..2026` ＋ `satSun`／`bizDay` 導出）に差し替える。短さを保ちたいなら、例の直後に「`TSE` は利用者が定義するカレンダー実体。動く形は [Playground の「月末の 3 営業日前」](https://kairos-lang.org/playground/) を参照」の 1 行を足す。doc-consistency の検査に「README のコードブロックは doctest で実行する」項を加えると再発しない。
