## RC2 → RC3（2026-07-08）

頻出しながら未定義だった土台の明文化と、最後の未確定機構の確定。受理の締め 2 件（`23:59:60` は字句エラー・DST の隙間と重複に落ちる時刻リテラルは明示エラー）。ADR-30/31 に改訂節。標準 premise は 4 本。

### ADR-33（TZ の定義）＝射影パラメータモデル

- 基底 chronos は TZ 非依存。TZ は市民座標への版付き写像で、「錨」は射影に付く。
- 市民日は「その日付になる最初の瞬間」からの半開区間。
- chronos はうるう秒を持たない一様な理想化軸。UTC の各日を 86,400 秒と数える（`23:59:60` は字句エラー）。
- DST の隙間・重複に落ちる時刻リテラルは明示エラー。解決規約は将来の opt-in。
- 紀元の tz 相対性を明文化。

### ADR-34（`label:` 付与式の束縛規則）

- ラムダは窓の**先頭点**を受ける。
- 意味論は定義的等式「`名前(d)` ≡ 付与式(先頭点)」（射影時・遅延評価）。
- 点±幅算術は導入しない。

### あわせて

- ADR-30/31 に改訂節。「別点の窓参照」の精密化・データ由来窓の `epochOrdinal` は存在する最初の窓が 0（F60）・`div`/`mod` の負数は floor（F63）。
- 用語集に TZ の項を新設。§3.6 の「うるう秒で 23〜25 時間」の誤記を修正。
- 標準 premise は 4 本に拡充済み（`../stdlib/`——Fiscal・ISOWeek・Kyureki と暦座標糖衣）。ISO 週番号が `label:` なしの確定語彙で書ける発見 F57 を含む。

## RC3 → RC4（2026-07-08）

最後まで残っていた二つの継続項目の確定。新構文はゼロ（ADR-35）。整列の静的検査を導入（ADR-36）。参照実装は実体・標準導出・整列検査まで追随し **147 テスト全通過**（doctest の標準前提も実体経由）。新出の宿題は F67〜F70（`../design/40-examples/90-findings.md`）。

### ADR-35（カレンダー実体の宣言・§3.9 新設）

- `calendar:` に立てる実体は、予約公開語 `nonWorking`（仮称）を持つ premise。新構文ゼロ。
- 正体判定（ADR-19 の延長）は `nonWorking` の day 整列と `tz:` 宣言（内側固定の執行点）まで要求する。
- `bizDay` は言語規定の標準導出（`calendar:` 在圏の予約名）。
- 軸位置の premise 名（`on: TSE`）は正体判定＋標準導出への読み替え（F53 解消）。
- 修飾ピンの member 解決規則（定義側優先）を明文化。

### ADR-36（結合子・軸所属の粒度整合・§4.5）

- **整列（alignment）**の静的検査を導入（F56/F54 解消）。
- 整列＝「全点が原子グリッド G（幅・正規化位相・tz 名）の目盛り上」という導出構造からの主張。
- `&`/`\`/`filter(on:)`/`roll(on:)`/`shift(unit: 点列軸)`/`stride` は両辺同一 G を要求。黙って空振りする形を静的エラーに。
- `snapTo` が明示の再整列。和 `|` は不問（混合スケジュール保護）。
- tz 名はリテラル文字列の等値。

### あわせて

## RC4 → RC5（2026-07-08）

**評価註釈（I6・ADR-15）の初めての具体化**（F61 解消）。EBNF に covering-list と束縛後置を追加。参照実装は註釈の区間輸送・包含検査・分類器・被覆サマリまで追随し **188 テスト全通過**。

### ADR-37（範囲外出自と covering: の活性化）

- `covering:` は「範囲内は完全・範囲外は未知」の二面の**主張**。**値には触れない**。
- 列の全要素の包含は静的検査。当初案の clip は敵対検証の致命反例で却下。
- 範囲外出自は結果に並走する**区間註釈**〔[a,b)・種・源・covering・asof〕。
- 相殺は自動でなく**明示の被覆主張**（束縛後置 `covering:`）のみ。
- エラーの分類器＝実効被覆域。外なら「落として註釈」、内なら従来どおり硬エラー。

### 輸送表（§4.10 新設）

- 伝播は core 全演算子の**輸送表**で定める。
- 結合子は和・shift は平行移動像・roll は依存像・選択子は窓拡幅・stride は位相汚染。
- segmentBy の `edges:` 発火は覆域端＝**実効被覆域**。

### 器と covering の表現域

- 器は二つ。評価範囲にクリップする区間註釈と、クリップしない**被覆サマリ**（源・covering・asof・完結主張・**残走路**）。
- covering の表現域を拡張。**開端**（`2021..`・`..`＝完結主張・統治つき）と**区間リスト**（中抜けの申告）。

### あわせて

- ADR-15/26 に改訂節（空の出自→区間の出自）。I6 の字面更新。
- EBNF（covering-list・束縛後置）。glossary 5 項追加。
- bizDay 標準導出の「データの尽きた先の黙った退化」（ADR-35 判断 3）が**退化するが観測可能**になる。
- 実装検証で判断 5 の必要条件検査を精密化（ADR-37 改訂）。判断 1 の `tz:` 必須の執行のみ宿題。

## RC5 追補 1（2026-07-08）——所属の意味論の縁の確定

F68・F70 解消。**ADR-38**。述語 `coincides` を新設し、stride のシグネチャから軸引数を削除（入力相対）。ADR-37 判断 4 の filter 輸送行を精密化。

### (a) 窓所属の述語 `coincides(S, w, d)`（§4.9 射影一族）

- 仮称三語目。値式の有界存在量化。
- 時刻付き・混合スケジュールへの例外日適用の受け皿（`filter(t => not coincides(closures, day, t))`——発火時刻を保存して「日」で除く）。
- 確定は**証人規則**。真＝非註釈区間の証人のみ・偽＝窓が実効被覆域内。
- S の市民時 tz と w の tz 名の不一致は静的エラー（クロス tz の裏口封じ）。
- 整列要求は課さない（区間所属＝ADR-36 判断 7 免除系へ）。

### (b) stride は入力相対

- 軸引数を削除。n ≥ 1 の整数。from: 以上の最初の入力点が第 0 歩。
- ADR-36 の stride 整列検査は削除。

### あわせて

- ADR-37 判断 4 の filter 輸送行を**逆像拡幅**に精密化（F75——窓越し述語の過小近似の穴）。
- 使い分けの規範「同じ**点**なら結合子〈snapTo で整合〉・同じ**所属**なら coincides」を §4.5 とエラー文言に整備。

## RC5 追補 5（2026-07-09）——位置依存の名前解釈と窓インスタンス参照

## RC5 追補 7（2026-07-14）——空テーブルリテラル（実装系還流の初便）

### 背景（F98）

## RC5 追補 9（2026-07-25）——テーブル後置の順序自由化と窓列被覆域の精密化（発報層還流 第 5 便）

第 3 の適用ドメイン（暦×占い）の実運用検証（発報層還流 第 5 便）が炙り出した 2 件。EBNF §5.6 を改訂（受理拡大）。正しく評価できていた式の意味は不変。

### テーブルリテラル後置の順序自由化（F104）

- `covering:`／`labels:` の後置を**順序自由・各一回**とする。EBNF §5.6 を `{ covering | labels }` 形に改訂。
- 従来文法は固定順（covering → labels）。実装は逆順の `covering:` を**ラベルリストの後置として黙って捨てて**いた。
- 受理拡大による封じ。二重指定は構文エラー。
- 既存の式の意味は不変（追加拡張）。

### 窓列の実効被覆域の精密化（F105・ADR-37 改訂 3）

- `segmentBy` の窓列は「窓の張られた範囲」だけを語る。
- マーカー覆域内でも窓のない区間（`edges: drop`/`error` の頭側・`empties: drop` の中抜け）は窓列由来の**範囲外註釈**。
- labels 射影・`coincides` の読みには「落として註釈」で応える。従来は硬エラーで、filter 派生マーカー〔覆域始端 < 最初のマーカー〕で filter 正準形が評価不能だった。
- エラー→註釈の緩和方向のみ。正しく評価できていた式の意味は不変。

## RC5 追補 10（2026-07-25）——窓列への周期ラベル `labels: cycle`（ADR-47）

`segmentBy` の `labels:` の値位置に周期形 `cycle リスト anchor: 実日` を追加。新語彙ゼロ。EBNF は segment-labels/cycle-labels を追加。既存の式の意味は不変（追加拡張）。

### 背景

- 発報層還流 第 5 便 §3 の実需。節切り月の十二支・月家九星・月星座など「窓列＝暦の単位・ラベル＝固定周期」の形。
- 候補設計を 4 視点で検証し、3 件の決定（2026-07-25）を経て採用。

### 意味論

- 窓束縛 cycle と同一「anchor の属する窓が先頭ラベル」＝ `list[(i − i₀) mod N]`。
- 同長性検査は課さない。covering が伸びても式不変＝ADR-46 静的ソース原則との整合。
- 守るのは位相の宣言のみ。マーカー中途増減・非周期列への誤用は機械検出されない（照合は doctest・`coincides` の分担）。
- anchor は窓列のいずれかの窓に区間所属。頭側・範囲外は明示エラー。
- 締めは静的 labels: と同一を継承。

言語は不変。参照実装 npm `kairos-lang` **1.0.12**・`kairos-lang-mcp` も同じ評価器を使うので揃う。束は 5 点＝範囲外シグナルの構築を軽く・`next` の確定再評価は `window-clip` を報告しない・`--ics` は点 0・註釈だけの範囲でも註釈の予定を書く・結果の出口にラベル・運用信号の文言と文書の揃え。小節は決定順。

### 範囲外シグナルの構築を軽く（2026-10-18）

- 評価器の内部シグナル `OutOfCoverageSignal`（範囲外の分類。ADR-37 判断 6）を組み立てる間だけ `Error.stackTraceLimit` を 0 にして、スタック採取を止める。組み立てが終わったら元の値に必ず戻す（try/finally）。
- 対象はこの 1 クラスだけ。他のエラー（`KairosError`・`SupplyError`）は 1 回限りの診断なので、従来どおりスタックを持つ。

変わらないもの:

- 結果（点・註釈・警告・被覆サマリ）と、`--json`／`--tsv`／`.ics`／MCP の出力。文言も同じ。
- 範囲外の分類と輸送（filter の「落として註釈」・窓の逆像への拡幅）。捕捉側は `instanceof` と `entries`／`window` しか読まない。
- 変わるのは速度と、このシグナルを例外として捕まえたときの `stack` 文字列（先頭行だけになる）。利用者の面には出ない。

理由: `at` 展開の内部述語は、覆域つき入力を参照すると覆域外の点を万単位で評価する。点ごとに投げる範囲外シグナルの構築（スタック採取）が支配項になっていた（実運用側の profile で自己時間の首位・33.9%）。採取を止めると出力は同じで 2.0〜2.5 倍（[design/90-open-questions.md](../design/90-open-questions.md) 2-1 ①。② tick 生成域の絞り込みは別途）。

### `next` の確定再評価は window-clip を報告しない（2026-10-19）

- `next` は見つかった後に [from, 最終発火日の翌日) で確定再評価する。右端は答えから決まるので、`shift(+1)` で最終発火日の翌日へ動く中間点が毎回 `window-clip` 警告になっていた（同梱例 `jp-holidays.kairos` の `next` 既定で再現）。値は正しいが、助言「範囲を広げて評価する」は `next` では実行できない。
- 確定再評価の `window-clip` を報告しない。外へ動いた点は from より前（次の発火ではない）か最終発火日の翌日以降（N 件の後）で、答えの N 件に含まれない。
- 変わらないもの: 点・註釈・残走路・`to`・終了コード。`list` の `window-clip`、地平線まで探して不足のときの `next`（`to`＝地平線＝`--horizon` で広げられる）、`horizon-clip` は従来どおり。`--json`／`--tsv`／`.ics`／MCP は同じ報告から出るので揃う。
- 採らなかった案: `to` を 1 日余らせる。`shift(+2)` や `roll` の週末越えには届かず、残走路と註釈の右端が 1 日ずれる。
- 文書: 発火層プロファイル A.4 の警告の註（日英）・`impl/README.md` の `next`。[design/90-open-questions.md](../design/90-open-questions.md) 2-6。

### `--ics`／`--ics-series`: 点 0・註釈だけの範囲は註釈の予定だけを書く（2026-10-19）

- 評価範囲に点が 1 つも無くても、範囲外の区間註釈があれば、註釈の予定（終日・`TRANSP:TRANSPARENT`）だけの .ics を stdout に書いて終了コード 0。stderr に「⚠ 点 0（[from, to) に点がない）・範囲外の註釈 N 件＝註釈の予定だけを書く」を知らせる（`--lang en` は英語形）。
- 点も註釈も 0 のときだけ従来どおり何も書かず、「⚠ 予定 0 件（[from, to) に点も範囲外の註釈もない）——.ics は書き出さない」で終了コード 2（`VEVENT` の無い `VCALENDAR` は出さない）。
- 件数の数え方（`icsEventCount`）を「点の総数」から「点＋範囲外の註釈」（予定の総数）に。Playground の「カレンダーに入れる」も同じ関数なので揃う（点 0・註釈だけでも作る。series の保存メッセージの「回数」は点の数のまま・点 0 のときは「予定 N 件」の形で知らせる）。
- 理由: 文書は「区間註釈は終日の予定として載る。表の外は黙らない」と言うのに、点が 0 の範囲では何も載らなかった。発火層プロファイル A.4（範囲外は信号であって評価不能ではない）に沿う。例: 同梱例 `jp-holidays.kairos` を `[2026-12-01, 2027-02-01)` で `--ics` すると、範囲外の帯 2026-12-31..2027-02-01 の 1 件だけの .ics になる。
- 変わらないもの: 点がある範囲の出力（予定・UID・名前・行の形）・`--json`／`--tsv`・MCP。言語は不変。
- 文書: `--help`（日英）・`impl/README.md`（`--ics`／`--ics-series` 節・終了コードの要約に `--ics` の予定 0 件＝2 を明記）・`recipes/windows-admin.md`（日英）。[design/90-open-questions.md](../design/90-open-questions.md) 1-6・5-3 (1)(2)。

### 結果の出口にラベルを添える（2026-10-19）

- 本体式が参照するラベル付き束縛（`external`／テーブルリテラルの `labels:`・`cycle`・`segmentBy` の `labels:`）が**ちょうど 1 つ**のとき、結果の各点 d に既存の射影 `B(d)` を評価して添える。
- ラベルの無い点（表に無い＝`shift` の後など・窓の外・範囲外）は `null`。参照が 0 か 2 つ以上なら添えない。

出口だけが変わる:

- `--ics`: 1 点 1 予定の形で、ラベルのある点は `SUMMARY`（と通知の文）が「名前 · ラベル」（「二十四節気 · 立春」）。名前を残すのは、`12` のような短いラベルだけでは予定が読めないため。`UID` は不変。`--ics-series` の 1 予定は名前のまま。
- 変わらないもの: 点・註釈・警告・被覆サマリ・人間表示。言語は不変（値層の点はラベルを持たない。読みは射影のまま＝ADR-30/39/47）。
- 出口の射影は後続の式の観測面を変えない: 射影が初めて強制した束縛のメモ化も巻き戻す（2026-10-24・レビュー所見）。準備中の版では、0 点の `filter` の述語内の名前を先行する式が射影で強制すると、後続の式の被覆サマリからその束縛の登録が消えていた（1.0.11 には出ていた）。

- 文書: `--help`（日英）・`impl/README.md`（`--json`・`--tsv`・`--ics` 節）・`recipes/excel-workday.md`（日英・見出し行）。[design/90-open-questions.md](../design/90-open-questions.md) 2-7。
